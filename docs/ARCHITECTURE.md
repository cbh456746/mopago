# 구조와 유지보수

정적 웹 앱입니다. 서버 측 계산·데이터베이스·로그인이 필요하지 않습니다. 공개 접속에는 GitHub Pages를 사용하고, 사용자 입력과 추천 계산은 브라우저에서 처리합니다.

## 입력에서 다음 수까지

1. 앱이 19종 조각 카탈로그와 하나의 단계별 분포를 구성합니다.
2. 같은 브라우저에 저장한 게임판·손패·능력 상태를 검증해 복원합니다. 과거 기본 17·18종 보드는 기존 조각 ID를 유지하면서 19종으로 확장합니다.
3. 배포 모델 하나를 읽고 규칙·카탈로그·분포 서명과 특징 형식을 검사합니다. 과거 모델을 대신 불러오는 경로는 없습니다.
4. 입력 변경을 300 ms 묶어서 새 추천을 요청합니다. 이전 Worker는 중단하고 요청 번호가 다른 오래된 응답은 무시합니다.
5. Worker가 모든 적법 첫 행동을 평가하고 빔 탐색으로 결과를 반환합니다.
6. 앱은 추천 카드와 보드의 배치 미리보기를 표시합니다. 다음 단계 버튼은 실제 사용자가 선택한 추천을 상태에 반영합니다.

## 보드와 아이콘

보드는 16개의 10비트 행 정수입니다. 능력 아이콘은 좌표·종류·생성 순서를 가진 별도 배열이며 최대 3개입니다. 따라서 같은 칸에 블록과 아이콘을 함께 표현할 수 있습니다. 가로줄 제거는 해당 행만 0으로 만들며 중력 이동을 하지 않습니다.

슬롯은 조각 ID와 함께 ready·used·pending을 구분합니다. pending은 아직 모르는 조각이며 used는 이번 세 조각 중 이미 사용한 조각입니다. pending을 used로 추측하거나 무작위 손패를 실제 결과로 채우지 않습니다.

## 추천과 학습의 경계

웹 Worker는 추천만 계산합니다. 학습·모델 선택·설정 변경 UI는 없습니다. 학습 CLI는 같은 추천 함수를 모의 게임에 적용하고, 실제로 출현하는 손패·아이콘만 환경 난수로 추첨합니다. 추천 탐색에는 미래 추첨 결과를 전달하지 않습니다.

학습과 모의 평가에서는 환경의 transition이 새 손패와 아이콘을 생성합니다. 실제 입력 보드의 ‘다음 단계로 진행’에서는 draw:false·spawn:false를 적용해 실제 추첨 결과의 수동 입력을 기다립니다. 바꿔 뽑기는 능력을 차감하고 해당 슬롯을 pending으로 만듭니다.

## 파일과 빌드

게임 규칙은 game.js, 추천은 expert-agent.js, 분포는 stage-distributions.js에 있습니다. 모델은 default.json 하나입니다. 규칙이나 조각을 바꾸면 환경 서명이 달라지므로 모델을 다시 학습하고 공개 평가를 갱신해야 합니다.

build.mjs는 정해진 앱 파일 6개와 모델 하나만 정적 출력에 복사합니다. 학습 스크립트·테스트·문서는 저장소에서 읽을 수 있지만 서비스 페이지에 묶지 않습니다. 배포 번호가 붙은 자산 경로로 캐시를 구분합니다.

브라우저 상태 키는 mopago.state.v1입니다. 사용자 게임판은 서버로 전송하지 않습니다. GitHub Pages 같은 호스트 내의 저장 공간은 공유되므로 다른 자체 앱과 충돌하지 않게 키를 유지하세요.

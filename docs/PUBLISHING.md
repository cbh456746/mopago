# 공개 저장소와 GitHub Pages

**저장소:** [cbh456746/mopago](https://github.com/cbh456746/mopago)

**웹 앱:** [모파고](https://cbh456746.github.io/mopago/)

## 포함한 자료

현재 게임 앱, 배포 모델 하나, 필요한 사용·규칙·확률·학습·설계 문서, 라이선스, 재현 스크립트와 규칙 검사 코드만 공개합니다. 구모델, 실패 후보, 원본 게임 화면·녹화, 개인 게임 상태, 중간 가중치, 로그는 포함하지 않습니다. 검사 소스는 유지보수에 필요한 코드이며 임시 실행 결과와 구분합니다.

dist·.local·환경 변수 파일·로그는 Git에서 제외합니다. 공개 저장소는 선별한 현재 파일로 시작하며 로컬 실험 저장소의 과거 이력을 업로드하지 않습니다. 커밋에는 허용한 공개 이름과 GitHub 비공개 이메일만 사용합니다.

## 배포 순서

1. Node.js 20 이상에서 npm test와 npm run build를 실행합니다.
2. dist에 index.html·.nojekyll과 배포별 앱 파일·모델 하나만 있는지 확인합니다.
3. 저장소 Settings → Pages → Source에서 GitHub Actions를 선택합니다.
4. main에 변경을 올리거나 Actions의 Deploy Mopago to Pages를 실행합니다.
5. Actions가 성공하면 공개 URL에서 세 조각 입력·추천 표시·다음 단계 진행을 확인합니다.

워크플로우는 내용 읽기 권한과 Pages 배포에 필요한 pages:write·id-token:write만 사용합니다. 인증 토큰이나 로컬 Git 자격 증명을 소스에 저장하지 않습니다. 커밋 후 GitHub Actions의 성공과 공개 파일의 실제 응답을 확인해야 배포 완료입니다.

## 배포 후 확인

- 기본 모델이 하나이고 해당 분포와 서명이 맞는지 확인합니다.
- 보드·아이콘 편집, 조각 입력과 추천 배치 미리보기를 확인합니다.
- 실제 추첨을 모르는 새 조각·아이콘은 수동 입력을 기다리는지 확인합니다.
- 다음 단계 진행과 되돌리기를 확인합니다.
- 좁은 화면에서도 보드·입력칸이 넘치지 않는지 확인합니다.
- 사용자 보드·분석 로그를 전송하는 코드나 외부 분석 스크립트가 없는지 확인합니다.

배포마다 자산 주소를 바꿔 오래된 JS·모델 캐시와의 혼용을 줄입니다. 기존 브라우저의 게임 상태는 유지하고 확률 가정과 추천 모델은 현재 배포본 하나로 적용합니다.

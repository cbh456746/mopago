# 한글 모아모아 알파고 · 모파고

메이플스토리 미니게임 **한글 모아모아**의 게임판과 보유 조각을 입력하면, 학습한 가치함수와 탐색으로 **다음 배치 또는 특수능력 사용**을 추천하는 독립 웹 도구입니다.

**[모파고 사용하기](https://cbh456746.github.io/mopago/)** · [프로젝트 소개](https://cbh456746.github.io/projects/mopago/) · [공식 게임 안내](https://maplestory.nexon.com/News/Event/Ongoing/1393)

설치나 로그인 없이 브라우저에서 사용합니다. 게임 화면을 자동으로 읽거나 게임 클라이언트를 조작하지 않습니다. 공개 화면에는 게임판·보유 조각·보유 능력·진행 상황·다음 수만 표시합니다.

## 처음 사용하는 순서

1. **게임판을 옮깁니다.** ‘■ 블록’ 도구로 현재 채워진 칸을 클릭하거나 드래그합니다. ‘칸 비우기’는 블록과 아이콘을 함께 지우고, ‘아이콘만 지우기’는 블록을 유지합니다.
2. **획득 전 능력 아이콘을 표시합니다.** ‘◎ 점 아이콘’ 또는 ‘↻ 교체 아이콘’을 선택하고 해당 칸을 누릅니다. 블록과 아이콘은 따로 저장되므로 채워진 칸에도 아이콘을 표시할 수 있습니다. 아이콘은 오래된 것부터 입력하세요.
3. **세 조각을 입력합니다.** 오른쪽 슬롯에 한글 자모 한 글자를 입력하거나 아래 버튼을 누릅니다. 한 칸짜리 조각은 마침표 `.`입니다. 이미 사용한 슬롯은 ‘사용 완료’로 표시합니다.
4. **보유 능력과 진행 상황을 맞춥니다.** 두 능력의 합계는 최대 7개입니다. 누적 ‘지운 줄 수’와 ‘다음 아이콘까지’ 남은 일반 조각 배치 횟수를 실제 게임에 맞춰 입력하세요.
5. **추천을 확인합니다.** 아래 추천 카드를 선택하면 황금색 칸으로 배치를 표시합니다. 좌표·회전·반전을 확인하고 실제 게임에서 실행합니다.
6. **‘다음 단계로 진행’을 누릅니다.** 이 페이지의 게임판과 사용한 슬롯을 갱신하고 다음 수를 찾습니다. 실제로 새로 나온 조각과 아이콘은 직접 입력합니다.

입력을 바꾸면 추천을 자동으로 다시 계산합니다. ‘다음 수 찾기’로 직접 요청할 수도 있습니다. 첫 추천 외의 대안 카드를 선택하면 해당 대안을 진행할 수 있습니다. 잘못 입력하거나 진행했다면 ‘되돌리기’를 누르세요.

### 조작과 표시

| 조작 / 표시 | 의미 |
| --- | --- |
| 숫자 1·2·3 | 입력칸 밖에서 해당 슬롯으로 이동 |
| Enter | 조각 입력칸에서 다음 슬롯으로 이동 |
| 방향키 / Space | 보드에 초점을 둔 뒤 칸 이동 / 현재 도구 적용 |
| 초록색 칸 | 현재 놓인 블록 |
| 황금색 칸 | 선택한 추천의 배치 위치 |
| 사선 무늬 | 해당 배치로 제거될 가로줄 |
| 진한 기준점 | 조각을 감싸는 직사각형의 왼쪽 위 |
| ◎ / ↻ | 보드에 남아 있는 획득 전 능력 아이콘 |
| ‘즉시 +N점’ | 해당 한 행동의 규칙상 점수. 최종 점수 예측이 아님 |

좌표는 왼쪽 위부터 **(열, 행)**을 1부터 셉니다. 기준칸 자체가 조각의 빈 부분일 수도 있습니다. 반전 표시가 있다면 **좌우반전을 먼저**, 표시한 각도만큼 **시계방향 회전을 다음에** 적용하세요.

세 조각을 모두 사용하면 새 세 조각의 입력을 기다립니다. 바꿔 뽑기를 진행하면 능력 1개를 차감하고 해당 슬롯의 실제 교체 결과를 기다립니다. 새 조각이나 아이콘 위치를 추측해 실제 결과인 것처럼 자동 입력하지 않습니다.

‘보드 비우기’는 보드와 보드 아이콘만 지웁니다. **‘초기화’는 모든 게임 상태를 처음으로 돌립니다.** 보드·아이콘·세 조각과 사용 상태를 비우고, 지운 줄 수·보유 능력·점수·아이콘 출현 주기를 0으로 초기화합니다. 추천과 되돌리기 기록도 지우며, 다음 아이콘까지 남은 배치는 처음의 7회로 돌아갑니다.

같은 브라우저에는 상태가 자동 저장됩니다. 초기화한 상태도 자동 저장되므로 새로고침해도 이전 게임이 복원되지 않습니다. JSON 파일로 상태를 저장하거나 불러오는 기능은 제공하지 않습니다.

## 반영한 게임 규칙

| 항목 | 내용 |
| --- | --- |
| 보드 | 10열 × 16행. 가로줄을 채워 지워도 다른 줄은 내려오지 않음 |
| 손패 | 세 조각을 모두 사용한 뒤 다음 세 조각 지급 |
| 방향 | 90° 회전과 좌우반전. 중복 모양은 제거 |
| 점수 | 일반 조각의 칸 수 + 동시에 n줄 제거 시 300 × n² + 능력 획득당 50 |
| 특수능력 | 점 찍기: 빈 칸 하나 채우기 / 바꿔 뽑기: 보유 조각 하나 재추첨 |
| 아이콘 출현 | 일반 조각 7회 배치마다 빈 칸에 생성. 점 찍기는 주기에 미포함 |
| 아이콘 종류 | 점 찍기 40%, 바꿔 뽑기 60% |
| 보유 제한 | 능력 합계 7개. 보드 아이콘 최대 3개, 초과 시 오래된 아이콘 제거 |
| 단계 | 누적 제거 줄에 따라 0~30 / 31~60 / 61~100 / 101~150 / 151줄 이상 |

19종 조각은 `ㅏ ㅑ . ㅍ ㄱ ㅌ ㅣ ㄷ ㅁ ㅡ ㅊ ㄹ ㅎ ㅇ ㅅ ㅈ ㄴ ㅋ ㅂ`입니다. 조각 표기와 확인된 규칙·미확정 사항은 [규칙 문서](docs/RULES.md)에 정리했습니다.

## 작은 조각 감소 규칙 공개

**완만한 감소 가정 하나만 사용합니다.** 균등 출현을 유지하는 별도 모델이나 구모델 선택 기능은 없습니다. 첫 단계의 시작 분포만 19종 동일 가중치이며, 이후 단계에서 작은 조각의 상대 가중치를 점차 줄입니다.

정확한 공식 조각별 확률표는 확인되지 않았습니다. 공식적으로 확인한 단계 경계와 감소 방향을 바탕으로 다음 **구현 가정**을 사용하며, 공식 확률이라고 주장하지 않습니다.

- 단계 `s`는 1~5, 조각의 칸 수 `k`는 1~10입니다.
- 단계별 감소 비율: `r(s) = 0.6^((s - 1) / 4)`.
- 조각 가중치: `w(s, k) = r(s)^((10 - k) / 9)`.
- 실제 추첨 확률: `P(조각 i | s) = w(s, k_i) / Σ w(s, k_j)`이며 합은 19종 전체입니다.
- 칸 수가 같으면 같은 가중치를 적용합니다. 구현은 가중치를 소수점 10자리로 반올림한 뒤 정규화합니다.

| 단계 | 누적 제거 줄 | 4칸 이하 조각의 합산 확률 |
| --- | --- | ---: |
| 1 | 0~30 | 36.8421% |
| 2 | 31~60 | 35.4385% |
| 3 | 61~100 | 34.0515% |
| 4 | 101~150 | 32.6833% |
| 5 | 151 이상 | 31.3360% |

5단계에서 **1칸 조각의 가중치가 10칸 조각의 0.6배**라는 뜻입니다. 1칸 조각이 60%로 나온다는 뜻이 아닙니다. 예를 들어 마침표 조각의 확률은 1단계 약 5.2632%, 5단계 약 3.9578%입니다. 전체 조각별 표는 [확률 문서](docs/PROBABILITIES.md), 구현은 [stage-distributions.js](src/stage-distributions.js)에서 확인할 수 있습니다.

## 모델과 성능

모파고는 **21개 상태 특징의 선형 가치함수와 빔 탐색**을 결합한 정책을, 모의 게임 전체의 보상으로 최적화한 프로젝트입니다. 계산량을 늘려 더 많은 후보 정책과 배치를 비교했으며, 배포에는 검증한 `models/default.json` 하나만 포함합니다.

빈 공간의 가로·세로 연결, 고립된 칸, 작은 틈, 거의 완성된 줄, 인접 줄과 아이콘의 줄 채움 정도 등을 평가합니다. 가능한 첫 행동을 모두 비교하고, **빔 폭 12·최대 3행동**을 탐색합니다. 재추첨은 19종 결과의 확률 가중 기대가치로 비교합니다. 알 수 없는 미래 조각·아이콘 위치를 미리 알려주지 않습니다.

목표는 **별도 평가 평균 100,000점 이상, P90 130,000점 이상**입니다. P90은 전체 점수를 오름차순 정렬해 `ceil(0.9 × N)`번째 점수를 선택하는 최근접 순위 방식입니다. 상위 10%의 평균과 다르며, 13만 점 이상 게임의 개수도 함께 공개합니다.

초기 정책 탐색 11,520게임에 공간 특징 추가 탐색 640게임을 더해 **총 12,160게임**을 완료했습니다. 후보 선택용 내부 검증과 최종 평가 게임은 학습 게임 수에 합산하지 않습니다. 자세한 실제 실행 기록과 재현 조건은 [학습·평가 문서](docs/LEARNING.md)를 참고하세요.

평가 수치는 위 출현 가정의 모의 환경에서 관측한 결과입니다. 정확한 공식 확률, 아이콘 위치 분포와 미확정 규칙이 다르면 실제 점수도 달라집니다. 관측 최고점은 이론상 최대점수나 실제 게임 보장이 아닙니다.

## 개발용 로컬 실행

공개 페이지 이용에는 설치가 필요 없습니다. 소스를 수정하거나 직접 학습하려면 **Node.js 20 이상**이 필요합니다. 외부 패키지 설치는 필요하지 않습니다.

~~~sh
npm start
~~~

`http://127.0.0.1:8878/`에서 열고 Ctrl+C로 서버를 종료합니다. 서버는 이 컴퓨터에서만 접근 가능한 루프백 주소를 사용합니다. HTML 파일을 직접 여는 방식은 ES 모듈·Worker·모델 로딩 때문에 지원하지 않습니다.

~~~sh
npm test
npm run build
npm run train -- 30 24 16
npm run tune
npm run evaluate -- .local/expert-candidate.json 500
~~~

학습 인수는 반복 횟수·후보당 게임 수·후보 수이며 기본 배포 모델에서 추가 학습합니다. 학습은 CPU 작업 스레드를 사용하므로 실행 시간은 컴퓨터 성능에 따라 달라집니다. 후보·로그·평가 원시 자료는 `.local/`에만 저장됩니다. 학습 명령은 공개 모델을 자동 교체하지 않습니다.

main의 변경은 GitHub Actions에서 테스트한 뒤 GitHub Pages에 배포합니다. 사이트 빌드는 앱 모듈과 모델 하나만 명시적으로 복사합니다. 모델·JS·CSS는 배포별 자산 주소를 사용합니다. 자세한 절차는 [배포 안내](docs/PUBLISHING.md)에 있습니다.

다른 에이전트가 작업을 이어받을 때는 [개발·GitHub·블로그 인수인계 설명서](docs/AGENT_HANDOFF.md)를 먼저 읽으세요. 저장소 구분, 기능·모델 검증, 블로그 글과 Home 수정, 개인정보 검수, 배포·복구 절차와 보류된 결정을 함께 정리했습니다.

## 개인정보와 공개 범위
